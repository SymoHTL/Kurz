# INDEX

One line per entry: a link plus a hook that carries the payload. Add your line WITH your entry, in
the same pull request. HARD = a trap that bit at least once; do not re-derive it, read the file.
TRAP = a trap caught before it cost. RECIPE = a working procedure. POSTMORTEM = the story.
LIVING = a diagram kept current with the system it draws.

## Design work

- [Design before build](knowledge/design-before-build.md) POSTMORTEM HARD — a v0 compiler was built before the big choices were asked and every pick in it was void (2026-10-01). In the design phase the tree gate refuses any path that is not design record, reference, corpus, knowledge or quality tooling. It is a rule about paths: compiler code under `tools/` is left to the review, and the CI run holds on every pull request and every push to main, though not on a branch without a pull request or a head commit with a skip literal; the write-time and pre-push hooks can be off (HAZARD #4).
- [Samples obey the rules beside them](knowledge/samples-obey-the-rules-beside-them.md) HARD — the cycle-rule section showed a class that its own rule rejects (2026-10-01). Nothing runs a sample, so read each one against every rule in its section before it goes in; samples in the design record and expectations in the corpus are unchecked (HAZARD #1).
- [A guarantee needs its mechanism](knowledge/guarantee-needs-its-mechanism.md) HARD — "durable state survives machine loss" was claimed for a log on that machine's own disk (2026-10-01). Write a guarantee as: the failure it survives, the mechanism, the cost; without a mechanism it goes under Open.
- [Reading a paper for evidence](knowledge/reading-a-paper-for-evidence.md) RECIPE — cite a figure only after reading its sentence in the source: extract the PDF with pypdf (on Windows set PYTHONIOENCODING=utf-8 when the output goes to a pipe or a file; 2026-10-01), record the workload, machine and baseline, link the paper.
- [A case bakes in a pick](knowledge/a-case-bakes-in-a-pick.md) HARD — writing the first conformance cases (2026-10-02) needed 33 rules the design record did not state on 2026-10-02 (`print`, block bodies, scope, what "used" means; round 7 wrote them in) and met 24 forks; the cases for each batch of answers met new ones (seven, then nine, then four, then none by round 10 on 2026-10-03), and the review of 2026-10-03 found fifteen more. A rule the record does not carry is `proposed` or `open` in the reference, never `decided`; the lint refuses a case on an open rule; a batch accepted with one word decides only the rules the question named, and an answer decides what its option said and nothing next to it.
- [Design change playbook](knowledge/diagram-design-change-playbook.md) LIVING — before, while and after writing a change to the design record: the owner chose it, each statement has one status, guarantees carry mechanism and cost, samples read against their rules, cross-references and Open checked across the whole record by hand, because the review sees only the diff; the reference rules that cite the changed sections follow in the same pull request.

## Publishing and the forge

- [A force push does not unpublish](knowledge/a-force-push-does-not-unpublish.md) HARD — after a history rewrite GitHub still serves the old commits by SHA and shows the force push with "Compare changes" (GitHub docs, read 2026-10-01). Only a fresh repository or GitHub Support removes them, and a clone made before the switch can publish the old history again with one push: delete it or re-point it. The gate for shapes is before the push: enable `.githooks/pre-push`. Future plans are a meaning, not a shape: nothing checks them before a push (HAZARD #2), so never write one into the tree. A push also publishes the author's address (HAZARD #12).
- [A private repository has no merge checks](knowledge/private-repo-has-no-merge-checks.md) HARD — on a free account, rulesets and branch protection answer 403 for a private repository (2026-10-01). This one is public for that reason; `merge-checks` is FAIL, not PARTLY, when the rules cannot be read or the ruleset is gone.
- [The forge fills ruleset parameters](knowledge/the-forge-fills-ruleset-parameters.md) TRAP — the ruleset created on 2026-10-01 came back from `gh api repos/<owner>/<name>/rules/branches/main` with `require_extra_approval_for_unattributed_changes: true`, which nobody had sent. `merge-checks` fails on any parameter the server carries and `tools/ruleset.json` does not name, so a new default becomes a decision instead of a surprise.
- [A skipped job reports success](knowledge/a-skipped-job-reports-success.md) TRAP — a job skipped by `if:` satisfies a required check, a workflow that never starts leaves it pending (GitHub docs, read 2026-10-01). The gates job has no `if:`; the review's required check is a commit status, not a job. A head with no `gates` run at all has a merge conflict or a skip literal in its head commit.
- [The review runs the default branch](knowledge/the-review-runs-the-default-branch.md) HARD — with pull_request_target the workflow, the reviewer and its rules come from the default branch: a change to the reviewer or its rules reviews nothing until it is merged, a stacked pull request is not reviewed in CI, and the pull request that introduced the reviewer had to be reviewed off-pipeline (2026-10-02). The `review` status proves only that some workflow run of this repository posted it, and a dispatch must be started on the default branch (HAZARD #11).
- [pull_request_target is blocked by default](knowledge/pull-request-target-is-blocked-by-default.md) TRAP — a public repository without an Actions event policy gets a default rule that blocks `pull_request_target`; since 2026-10-03 the owner's policy allows the event and `workflow_dispatch` for `review.yml` (one `restrict_action_events` rule with both events; a policy with no rules has no visible effect, and nothing asserts the policy: HAZARD #10). For a Ready pull request whose `review` stays pending, look for a `review` run of that head first; without one, dispatch `review.yml` on the default branch.
- [A paid result is printed before it is posted](knowledge/a-paid-result-is-printed-before-it-is-posted.md) POSTMORTEM HARD — the first full review posted 40 comments in a row, GitHub's secondary rate limit refused the rest, and 88 findings that lived only in memory were lost (2026-10-02). On 2026-10-03 the second review printed 235 of 237 findings and died on an arrow: a redirected stdout on Windows takes the console's code page. Print a result that cost money in full, into a log that takes every character, before the first post; pace posts a second apart; wait and resend on that refusal, never after a write that got no answer; stop posting once the waits are spent.
- [A cancel does not beat the runner](knowledge/a-cancel-does-not-beat-the-runner.md) POSTMORTEM HARD — the review run that Ready starts was cancelled on 2026-10-07 while the forge still listed it as queued, and ran two paid passes before the runner got the signal; a run that started is a bill, so a head reviewed off the pipeline is labelled `reviewed-<its sha>` and the job skips its Ready event; every other head is reviewed and billed
- [The combined status drops the creator](knowledge/the-combined-status-drops-the-creator.md) POSTMORTEM HARD — GitHub's combined status (`commits/{ref}/status`) lists each status without its creator, so the merge tool's pinned-poster filter read the first real `review` status as absent while the forge called the head mergeable (2026-10-07); read the list of statuses (`commits/{ref}/statuses`), which names the creator and holds every status ever posted for the ref, and take the newest status of the context from the pinned poster, ignoring a status from another creator however new it is. The fixture of the combined endpoint had been captured before any status existed, an empty list no case could fail on: capture again once the platform has sent the thing, and give the case a floor.
- [Resolve what the edit answered](knowledge/resolve-what-the-edit-answered.md) RECIPE — after the fix push, `py -3 tools/pr_gates.py resolve --pr N --head <pushed sha>` lists the reviewer threads the head's edits answer and the ones left open with the reason; `--go` resolves the former, a second apart. The reading of an edit is the findings gate's: every file of the finding changed since the finding's commit. Two pull requests had it as a hand-written script before the third need made it the tool (2026-10-07).
- [The pull request shows the old head after a push](knowledge/the-pull-request-shows-the-old-head-after-a-push.md) TRAP — read one second after a push, the pull request still named the old head; a minute later it named the new one, and 15 seconds after the next push (2026-10-08): the resolve tool had compared the finding's commit with itself and reported the answered thread as "the file did not change". Pass the pushed commit: `py -3 tools/pr_gates.py resolve --pr N --head <sha>` refuses while the pull request shows another head; run it again until it runs, then `--go`.

## Tools

- [Claude CLI headless answer](knowledge/claude-cli-headless-answer.md) TRAP — an API error, a wrong credential included, still says `"subtype": "success"` (CLI 2.1.283, probed 2026-10-01 and 2026-10-02). Decide on `is_error`, the exit code and `structured_output`; check `modelUsage` for the pinned model. The entry has the flags for a call with no tools.
- [A headless call inherits its session](knowledge/a-headless-call-inherits-its-session.md) TRAP — a CLI call started inside an agent session takes that session's effort and switches from the environment, `--safe-mode` does not stop it, and with the inherited variable set `--effort` changed nothing (probed 2026-10-02). Hand the call an allow-list of variables and pin the effort beside the model, as the reviewer does.
- [What a review pass costs](knowledge/what-a-review-pass-costs.md) HARD — measured on 2026-10-02 at that day's list prices: one pass over a 30k-character batch thinks 60k to 120k tokens and takes 6 to 19 minutes, whatever the model and the effort the CLI was given (through the reviewer's allow-list environment, not a session's); about 1.3 to 1.8 USD on `claude-opus-5-5` (the entry's table: 1.35 to 1.75), 3.5 to 4.3 on `claude-fable-5-1`, with no better findings for the price. The first full review of a 20-batch pull request was 30 passes and about 45 USD at list price, an estimate. Count the batches with `review.py --plan` and name the bill: a run in CI starts without a question since 2026-10-07, a run off the pipeline waits for the owner's go-ahead; keep diffs small; lows go to one issue and hold no merge.
- [Stale bytecode hides a mutation](knowledge/stale-bytecode-hides-a-mutation.md) HARD — Python reuses a `.pyc` when the source has the same size and the same second of modification, so two equally long mutations of `tools/kit.py` ran as the first one, in CI only (2026-10-01). The red-proof replay writes no bytecode; a harness that rewrites source and runs it again must not let the interpreter cache it.
- [A re-serialized ledger is a whole-file diff](knowledge/a-re-serialized-ledger-is-a-whole-file-diff.md) TRAP — a script that writes a file back in another style than it was written in makes every line a change the review reads and bills: the ledger has one form (one entry per line, two spaces in, text as it is), the self-tests refuse another, and `tools/red_proof.py --format` writes it (2026-10-09)
- [A local run reads the working tree](knowledge/local-run-reads-the-working-tree.md) HARD — a local gates run reads the files on disk, untracked ones included, and CI reads the commit plus what the job itself wrote; the first CI run was red on a bytecode directory no local run had made (2026-10-01). When the verdicts differ, run `git status --porcelain --untracked-files=all --ignored` before reading any code.
- [A hook denies by exit 2 or by its JSON](knowledge/a-hook-denies-by-exit-2-or-by-its-json.md) TRAP — a PreToolUse hook blocks a tool call by exit 2, whatever it prints, or by a JSON decision `deny`, which the harness reads on every exit code (the page's words: "on every exit code, not just 0"); every other end lets the call through, a crash, a timeout and a missing interpreter included (Claude Code docs, read 2026-10-08 and again 2026-10-09). The write-time hook here prints no JSON, and its command turns every end but 0 into exit 2.
- [Git stores a lone carriage return as binary](knowledge/git-stores-a-lone-carriage-return-as-binary.md) TRAP — under `* text=auto eol=lf`, git 2.53.0 stored a CRLF file as LF and left a file with a lone carriage return byte for byte, judging it binary (one probe, 2026-10-08); a corpus case that expects a carriage-return byte marks its path `-text`, and the git of the CI image is pinned by nothing (HAZARD #15).
- [YAML plain scalar traps](knowledge/yaml-plain-scalar-traps.md) HARD — in a YAML list a colon-space turns a bullet into a mapping and a leading quote ends it early; PyYAML keeps the last of two duplicate keys silently (2026-10-01). Quote the bullet or use `>-`, and read YAML through `kit.load_yaml`, which refuses a repeated key.

## The quality bar

- [Gate map](knowledge/diagram-gate-map.md) LIVING — every gate, hook, server-side rule and process law by where it runs, with what turns it red or the HAZARD issue that stands in for it; a "review rule" named as a gate is a model reading one batch of a diff.
- [The walk one change takes](knowledge/diagram-change-walk.md) LIVING — branch, local gates, push through the pre-push hook, Draft, gates job, Ready, review on the default branch's rules, threads answered by edits, lows on one issue, merge of the exact head through the tool; and the places where the local gates, the gates job, the review and the merge send it back, with the remedy for every way a review run can fail.
- [Knowledge routing](knowledge/diagram-knowledge-routing.md) LIVING — where a fact goes: decisions to the design record, rules to CLAUDE.md, each with its gate, its HAZARD issue or the judgment-step label, lessons to knowledge/, open work to issues, and anything machine-bound or about future plans to private memory, never here; a lesson is promoted out of private memory only when nothing in it has a reason to stay local.
- [Quality bar guide](guides/quality-bar.md) — which file, job or setting implements each law of the quality bar here; what GitHub does differently from GitLab (a skipped job reports success, a bypass list exists and is kept empty, lows go to an issue); and what is not implemented, each with its HAZARD issue or reason.
- [Quality bar evidence](guides/quality-bar-evidence.md) — generated numbers for gates, self-tests, red proofs, the store and the forge. They carry a digest of the blocks, the date and the TTL that a hand edit leaves stale (a recomputed one passes: HAZARD #18) and expire after `ttl_days`: the `knowledge` gate is then red on every pull request and on `main` until a pull request brings the page `tools/quality_evidence.py` regenerated.
