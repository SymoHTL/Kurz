- [The run floor is measured, not merged](knowledge/the-run-floor-is-measured-not-merged.md) RECIPE — `RunFloor` in `RunTests.cs` is each system's count of corpus cases run, with no margin, so where a branch and `main` both changed it neither number is the merged count (486 and 461, merged 495, 2026-11-06); set the system's number to 999, run `At_least_the_floor_of_cases_are_built_and_run` and take the count its message prints; Windows is measured only by `compiler-windows`
- [A corpus case is filtered by its display name](knowledge/a-corpus-case-is-filtered-by-its-display-name.md) TRAP — the corpus suites are `[Theory]` rows whose case path stands in the display name alone, so a filter by `FullyQualifiedName` and the case's name reached no test of `http/serve-stream-length.kz` and the run said 1 test, 0 failed (pull request 428, 2026-11-09): filter by `DisplayName~<path>` and read the count of tests the run names, 5 for a case built and run.
- [A BigInteger converts to a double by cutting](knowledge/a-biginteger-converts-to-a-double-by-cutting.md) TRAP — on .NET 10 `(double)` of a `BigInteger` cuts the bits past the 53rd, where `(double)` of a `ulong` or a `long` rounds to the nearest, ties to even, as LLVM's `uitofp` and `sitofp` do in the program: 2^53 + 3 gives 2^53 + 2 against 2^53 + 4, and 2^63 - 1 gives 2^63 - 1024 against 2^63 (probed 2026-11-10, after pull request 423). The checker holds an integer constant as a `BigInteger`, so a fold that must give the program's `double` converts through the C# type of the program's integer, and its test takes 2^53 + 3, never the tie 2^53 + 1.
- [A test of .NET's own text breaks on a runtime patch](knowledge/a-test-of-dotnets-own-text-breaks-on-a-runtime-patch.md) TRAP — on 2026-11-10, the day .NET runtime 10.0.15 was released, the Windows job's install step took it up between two runs on the same runner image, and 10.0.15 writes 2^-958 and 2^-25 with the digits the program writes, where 10.0.14 writes 16 digits that read back as other values; the `FloatingTests` assertion that listed them as .NET's misreads went red on a head that touched neither. The test accepts a subset of the two and holds the program's text for both: a test of what a dependency itself does names the version where that changed, or accepts both.
